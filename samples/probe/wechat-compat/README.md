# 公众号排版与 SVG 兼容性探针

测试文件：`probe.html`。L01–L05 测基础样式、Flex、Grid、定位和表格；S01–S05 测 SVG 箭头引用、自动动画、点击切换、点击动画和动画 ID 事件链。每个测试编号都应单独记录结果。

## 比较路径

1. 原始 HTML 在桌面 Chrome 打开，记录视觉和操作基准。S03 的实际点击结果应先记录；如基准自身失败，不将其归因于微信。
2. 将文件导入项目的公众号转换页，记录预览和复制输出。输出与原始不同的样本，在进入微信前已被项目降级。
3. 将复制内容粘贴到公众号后台新建的测试草稿，记录编辑器即时效果；保存后重新打开，逐项记录。
4. 使用后台手机预览，在 iOS / Android 微信分别核对自动播放、点击及布局。记录客户端版本、日期、粘贴方式和实际差异。
5. 不要发布该测试草稿；手机预览前确认接收方式不会向非预期对象发送内容。

结果标记：通过 / 失败 / 部分 / 未测；不能把 Chrome 预览或剪贴板 MIME 当成公众号保存、手机预览通过。

## 根据当前证据的规则建议

- 保留 SVG 内部引用 ID，并在转换前后检查引用是否完整；当前本地代码已保留 SVG 内 ID。
- L02/L03 已变为表格，L04 的定位被降级。要评估微信原生支持，必须把原始和转换结果分别送入后台并测试，不能据本地预览贸然放宽默认规则。
- 自动动画与点击事件属于独立测试项；即便标签保留，也需要验证编辑器粘贴、草稿重开、移动端运行三个环节。
